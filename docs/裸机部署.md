## Part A：服务器（DGX Spark，三服务）

### A1. 系统要求
- **DGX Spark**（GB10 Grace Blackwell，128GB 统一内存，系统显示 ~119GiB）
- Ubuntu 24.04 · CUDA 13.0 · 驱动 580.82.09 · Docker 28.3.3
- 20 核 CPU · NVMe 3.7TB
- ⚠️ GB10 是 aarch64 + 统一内存，`nvidia-smi memory-usage` 显示 `Not Supported` 属正常，看 `free -h`

### A2. Docker + vLLM 镜像
```bash
docker pull eugr/spark-vllm:latest   # 含 nightly vLLM 0.23.1rc1（GB10 适配）
```

### A3. 模型下载（modelscope，**不要用 hf-mirror**）
```bash
# 装 modelscope（用 venv，见 A4）
~/reproforge/.venv/bin/pip install modelscope
~/reproforge/.venv/bin/python - <<'PY'
from modelscope import snapshot_download
import os
HOME = os.path.expanduser("~")
print("下 Qwen2.5-VL-7B-Instruct (~15GB)...")
snapshot_download("Qwen/Qwen2.5-VL-7B-Instruct", local_dir=f"{HOME}/models/Qwen2.5-VL-7B-Instruct")
print("下 bge-large-zh-v1.5 (~1.3GB)...")
snapshot_download("BAAI/bge-large-zh-v1.5", local_dir=f"{HOME}/models/bge-large-zh-v1.5")
PY
```
> 文本模型 `qwen36-35b-a3b` 若机器预装在 `~/models/` 则跳过；否则同样 modelscope 下。

> ⚠️ **不用 hf-mirror**：大 safetensors 走 Xet CAS 协议反复超时（`read operation timed out`）；modelscope（Qwen 官方镜像）稳。

### A4. bge 服务依赖（Python venv）
```bash
python3 -m venv ~/reproforge/.venv
~/reproforge/.venv/bin/pip install \
    sentence-transformers fastapi uvicorn torch \
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```
> bge 走 CPU（不占 GPU 显存，峰值可控的关键）。comfyui-env 路径在该机器不一致且有缺失，**用自建 venv**。

### A5. 部署脚本 + 起三服务
```bash
# 从本地 scp 脚本（小文件，OK）
scp -P 6071 -r deploy/spark71 Developer@<spark-ip>:~/reproforge_serve/
ssh -p 6071 Developer@<spark-ip>
cd ~/reproforge_serve && bash start_all.sh   # 下模型 + 起三服务 + 健康检查
```
三服务（`start_all.sh` 编排）：
- **文本 vLLM** `:8000`：qwen36-35b-a3b，util 0.45，`-e VLLM_USE_DEEP_GEMM=0`
- **VL vLLM** `:8001`：Qwen2.5-VL-7B-Instruct，util 0.3，`--limit-mm-per-prompt '{"image":1}'`
- **bge** `:8002`：FastAPI + sentence-transformers，CPU

### A6. ⚠️ 实测坑（6 个，部署必读）
1. **必须 `-e VLLM_USE_DEEP_GEMM=0`**：nightly DeepGEMM 在 GB10 NVCC JIT 编译失败，容器 ~40s 后 Exited。
2. **VL `--limit-mm-per-prompt` 要 JSON**：`'{"image":1}'`（不是 `image=1`，vLLM 0.23 用 json.loads）。
3. **文本 0.45 + VL 0.4 占满 119GB**：双实例 CUDA context×2 开销超预估，VL 降到 **0.3** 才留 ~11GB。
4. **模型用 modelscope**（非 hf-mirror，见 A3）。
5. **bge 走 `~/reproforge/.venv`**（comfyui-env 缺失）。
6. **chromadb 1.x EF 协议**：自定义 embedding function 须实现 `__call__` + `embed_documents` + `embed_query` + `name`。

### B4. whisper 模型（首次下，hf-mirror）
首次「语音转口述」会下 whisper small（~480MB）。设环境变量（或写进 `.env`）：
```bash
HF_ENDPOINT=https://hf-mirror.com
HF_HUB_DISABLE_XET=1
HF_HUB_OFFLINE=1          # 下完后设 offline（不连 HF，秒转）
```
首次手动预热：`HF_ENDPOINT=... HF_HUB_DISABLE_XET=1 python -c "from faster_whisper import WhisperModel; WhisperModel('small', device='cpu', compute_type='int8')"`

## 常见问题
| 现象 | 处理 |
|---|---|
| vLLM 启动 ~40s Exited | 必须 `-e VLLM_USE_DEEP_GEMM=0`（坑 1）|
| VL `--limit-mm-per-prompt` 报错 | 用 JSON `'{"image":1}'`（坑 2）|
| 双实例显存占满 | 文本 0.45 + VL **0.3**（坑 3）|
| 模型下载超时 | modelscope（非 hf-mirror，坑 4）|
| chromadb `AttributeError name` | EF 实现 embed_documents/embed_query/name（坑 6）|
| whisper ASR 连不上 | `.env` 加 `HF_HUB_OFFLINE=1`（下完后）|
| 复现慢 / minimize 卡 | min_runner 用确定性 spec（不每次 LLM）+ `REPROFORGE_RUNS=3` |
