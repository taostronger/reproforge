# 使用方式

> 从零到跑通 ReproForge，含开发态（远程）与演示态（本地三服务）两种配置。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| Python | 3.12+ |
| Node.js | 18+（被测商城用 Vite）|
| 浏览器 | Playwright 自带 chromium |
| DGX Spark（演示态）| spark-71 或同级 GB10 机器，三服务已部署 |
| Stepfun API Key | 远程 LLM / fallback 用（开发态主用）|

## 2. 安装

### 2.1 Python 依赖

```bash
pip install langgraph openai pydantic python-dotenv faster-whisper \
            tree-sitter tree-sitter-typescript gradio pytest \
            chromadb requests opencv-python imageio-ffmpeg sshtunnel paramiko \
            -i https://pypi.tuna.tsinghua.edu.cn/simple
pip install playwright && playwright install chromium
```

> RAG 的 embedding 走远程 bge 服务，**本机不需要 sentence-transformers / torch**。

### 2.2 被测商城

```bash
cd demo_project
npm install
npm run dev          # 启动在 :5173
```

商城预埋 3 个 Bug（优惠券 / 优惠码提示 / 删除归零），供演示。

## 3. 配置环境变量

```bash
cp .env.example .env
```

`.env` 关键项（完整见 `.env.example`）：

### 开发态（远程，迭代快、不占本地显存）

只设 Stepfun key，不设 `LOCAL_*`：

```bash
STEPCONFIG_FUN_API_KEY=<你的key>
# LOCAL_* / EMBEDDING_BASE_URL 留空 → 纯远程 stepfun
```

### 演示态（本地为主 + 远程 fallback）

先在 spark-71 部署三服务（见 [`架构与部署.md`](架构与部署.md)），本地建隧道后：

```bash
STEPCONFIG_FUN_API_KEY=<你的key>          # 远程 fallback
LOCAL_BASE_URL=http://localhost:8000/v1    # 文本 vLLM（隧道）
LOCAL_MODEL=/models/qwen36-35b-a3b
LOCAL_VL_BASE_URL=http://localhost:8001/v1 # VL vLLM（隧道）
LOCAL_VL_MODEL=/models/Qwen2.5-VL-7B-Instruct
EMBEDDING_BASE_URL=http://localhost:8002   # bge embedding（隧道）
REPROFORGE_VL=on
REPROFORGE_MEMORY=on
```

> 调用逻辑：文本 / VL 本地优先，本地连不上 / 超时 / 5xx → 自动 fallback 远程 stepfun。开发态（无 `LOCAL_*`）等同纯远程。

## 4. 部署 DGX Spark 三服务（演示态）

```bash
# 1) 部署脚本到 spark-71（小文件 scp）
scp -P 6071 -r deploy/spark71 Developer@<spark-ip>:~/reproforge_serve/
# 2) 一键起三服务（下模型 + 起文本/VL vLLM + bge，含健康检查）
ssh -p 6071 Developer@<spark-ip> 'cd ~/reproforge_serve && bash start_all.sh'
# 3) 本地三端口隧道（前台保持开）
bash scripts/tunnel.sh
```

三服务就绪（启动预热约 2-3 分钟 / 实例）后，`:8000 / :8001 / :8002` 经隧道在本地可达。显存占用与实测坑见 [`架构与部署.md`](架构与部署.md)。

## 5. 运行

### 5.1 Gradio UI（推荐）

```bash
python -m ui.app     # http://localhost:7860
```

UI 是步骤式：① 输入 Bug 信息 → ② 运行复现流水线 → ③ 查看结果。商城右上角「🐞 Report Bug」可跳入 ReproForge。

### 5.2 冒烟脚本（端到端真调验证）

```bash
python spike/smoke_phase3.py            # 主流程（evidence→reproduction→...）
python spike/smoke_vl.py 截图.png       # VL 视觉（本地 Qwen2.5-VL）
python spike/smoke_rag.py               # RAG 记忆（本地 bge embedding）
python spike/smoke_fallback.py 截图.png # fallback 链路（本地挂→远程兜底）
```

### 5.3 单元测试（全 mock，不依赖服务）

```bash
pytest tests/ -k "not smoke"
```

## 6. 四种输入方式

| 输入 | 怎么用 | 转化 |
|---|---|---|
| 🖱️ 录制网页操作 | UI 点「录制」，在商城操作，停止后得 actions | Playwright 监听 click/fill/goto → actions[] |
| 🎬 上传视频 | UI 上传录屏 | imageio-ffmpeg 提音频 + whisper ASR + opencv 抽帧 + LLM 提操作/口述 |
| 🎤 语音口述 | UI 录音 | faster-whisper（CPU int8）→ 带时间戳口述文本 |
| ✍️ 手填 | UI 填 JSON 操作 + 上传截图 | 直接 actions[] + screenshot |

可选上传 Bug **截图**（VL 视觉节点用，提 expected/actual）。无截图则跳过 vision，走口述。

## 7. 输出解读

一次完整运行产出：

1. **复现结果摘要**：`success` / 稳定率（如 3/3）/ 最小复现是否求得；
2. **VL 视觉提取**（如启用）：expected / actual / 页面描述 / 置信度；
3. **生成的 Playwright 测试代码**：`getByTestId` 定位 + 断言，可直接 `npx playwright test`；
4. **最小复现步骤**：人类可读的稳定 1-minimal 复现序列；
5. **Bug Issue（Markdown）**：标题 / 预期 / 实际 / 最小复现步骤 / 稳定率 / 可疑代码 / 截图；
6. **历史记忆**：本次 Issue 自动 ingest 进记忆库，供后续相似 Bug 检索。

## 8. 回归验证闭环（演示要点：buggy 失败 → fixed 通过）

ReproForge 生成的测试断言**预期值**（expected），是标准回归测试：**buggy 版本失败、fixed 版本通过**——这是最有说服力的「证明 Bug 被复现 + 修复被验证」闭环。

商城 demo 预置 Bug1（优惠券总价 apply 时只算一次，数量变化不重算），并支持 `?fixed=1` 切到修复版（总价随数量实时重算）。用同一测试 `demo_project/regression-bug1.spec.ts`（断言 `total-price = 160`）：

```bash
cd demo_project && npm run dev          # 商城 :5173
# 另开终端，跑回归验证（同一断言）
npx playwright test regression-bug1.spec.ts
#   buggy（默认 http://localhost:5173/）      → actual 80  ≠ 160 → 测试失败 = 复现 Bug
#   fixed（http://localhost:5173/?fixed=1）   → actual 160 = 160 → 测试通过 = 回归验证
```

路演可手动对比：先在 `http://localhost:5173/`（buggy）演示 Bug 复现（总价 80），再在 `http://localhost:5173/?fixed=1`（fixed）演示修复后通过（总价 160）——**同一操作、同一断言，修复前失败、修复后通过**。

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 本地服务慢 / 超时 | 检查隧道是否开；日志见 `[fallback]` 自动切远程属正常加固 |
| VL 未生效 | 确认上传了截图；`REPROFORGE_VL=on`；本地 VL 实例预热完（`curl localhost:8001/v1/models`）|
| RAG 检索为空 | 首次运行记忆库为空（冷启动），跑过一次后才有历史；`EMBEDDING_BASE_URL` 已设 |
| Playwright 定位器失败 | reproduction 有 2 轮自修复（testid→role→placeholder 降级），仍失败见终端报错 |
| vLLM 启动 Exited | 必须 `-e VLLM_USE_DEEP_GEMM=0`（见部署文档坑 1）|
