# 模块架构

> 各模块的职责、接口、依赖与协同。配合 [`架构与部署.md`](架构与部署.md)（系统级数据流）阅读。

## 0. 模块总览

| 模块 | 职责 | 关键入口 |
|---|---|---|
| `graph/` | LangGraph 编排，串联 6 节点 | `run_pipeline()` |
| `agents/` | 6 个业务 Agent（vision/evidence/reproduction/recall/code_investigator/regression）| 各节点 `analyze_screenshot` / `build_timeline` / `reproduce` / `recall` / `investigate` / `review` |
| `llm/` + `config` | 统一模型抽象（本地优先 + 远程 fallback）| `chat` / `chat_json` / `chat_vision` |
| `memory/` | RAG 记忆库（chromadb + 远程 bge）| `MemoryStore` / `get_memory_store()` |
| `capture/` + `asr/` | 操作录制 + 视频解析 + 语音转写 | `record_user_session` / `parse_video` / `transcribe` |
| `test_runner/` | Playwright 执行器（连跑判稳定）| `run_n_times()` |
| `minimization/` | 最小复现算法（核心创新）| `minimize()` |
| `code_search/` | ripgrep + tree-sitter 检索 | `search()` |
| `ui/` | Gradio 步骤式界面 | `build_app()` |
| `eval/` | 评测指标 + 远程 vs 本地对比 | `run_eval()` / `compare()` |
| `deploy/spark71/` + `scripts/` | DGX Spark 三服务部署 + 本地隧道 | `start_all.sh` / `tunnel.sh` |

## 1. 编排层 `graph/workflow.py`

把 6 节点线性串联成 LangGraph StateGraph。

- **`State(TypedDict)`**：流水线状态，字段含 `actions / segments / console_log / screenshot / visual_finding / timeline / repro_result / historical_ref / top_files / issue` 等；
- **6 个节点函数**：`vision_node / evidence_node / reproduction_node / recall_node / investigator_node / regression_node`，各读 state、调对应 agent、返回 state 增量；
- **`build_graph()`**：构造 `START → vision → evidence → reproduction → recall → investigator → regression → END`；
- **`run_pipeline(actions, segments, console_log, repo_path, project_dir, screenshot)`**：对外入口，编译图、注入初始 state、跑完后 `_ingest_to_memory(state)` 把 Issue 写入记忆库。

> 依赖：`agents/*`、`memory/`、`llm/`。vision / recall 节点对失败/空输入返回空，移除后图仍可跑。

---

## 2. Agent 层 `agents/`（6 节点）

### 2.1 `vision.py` — VL 视觉
- `VisualFinding(expected, actual, page_description, confidence, needs_confirm, used)`
- `analyze_screenshot(screenshot, narration) -> VisualFinding`：本地 Qwen2.5-VL 优先（`chat_vision`），看截图提 expected/actual；无图/失败 → 空 finding（`used=False`）。
- 辅助 `_to_data_uri()`：本地图转 base64 data URI（远程 API 访问不了 file://）。

### 2.2 `evidence.py` — 证据分析
- `TimelineEvent / BugTimeline(events, expected, actual, needs_confirm)`
- `build_timeline(actions, segments, console_log, visual_finding) -> BugTimeline`：按时间戳把语音 segment 关联到最近操作；启发式扫异常词；`chat_json` 提 expected/actual；与 visual_finding 按置信度合并。
- 辅助 `_nearest_segment()` / `_looks_anomalous()`。

### 2.3 `reproduction.py` — 复现工程（流水线最重）
- `ReproductionResult(success, spec_code, minimized, stable_rate, rounds, reason)`
- `generate_test(steps, expected, actual, base_url)`：LLM 生成 Playwright (TS) 测试（`getByTestId` + 断言）；`_strip_fence` 剥围栏、`_ensure_import` 补 import。
- `fix_locator(spec_code, error_msg)`：按报错修定位器（testid→role→placeholder 降级）。
- `reproduce(timeline, ...)`：循环最多 3 次（1 初始 + 2 修定位器）——`run_n_times(spec,3)` 连跑判稳定；3 次全失败=稳定复现，全通过=无 Bug，否则 fix_locator 重写再跑；稳定后调 `minimize`。

### 2.4 `recall.py` — 记忆检索
- `HistoricalRef(items, used)`
- `recall(timeline, actions, store, top_k=3) -> HistoricalRef`：store 为 None / 库空 / 失败 → 空，investigator 照旧。

### 2.5 `code_investigator.py` — 代码调查
- `FileScore(path, score, reason, snippet, context)` / `TopFiles(files, query_terms)`
- `investigate(timeline, console_errors, repo_path, historical_ref) -> TopFiles`：`_extract_query_terms`（排除纯数字噪声）→ `code_search.search` → `chat_json` 对每文件打分；`_format_historical_ref` 把历史参考注入打分 prompt。**只排序可疑文件，不宣称根因**。

### 2.6 `regression.py` — 回归审查
- `Issue(title, expected, actual, minimal_steps, stable_rate, suspected_files, body)`
- `review(spec, timeline, top_files, repro_result) -> Issue`：结构字段确定性组装 + `chat` 审核/生成 Markdown Issue；LLM 失败 → `_fallback_body` 确定性组装。

## 3. 模型层 `llm/client.py` + `config.py`

统一 OpenAI 兼容抽象，**本地优先 + 远程 fallback**。

- **`config.py`**：`get_local/remote_model_config()`（文本）、`get_local/remote_vl_config()`（VL）；`LOCAL_*` 环境变量决定本地路径；旧 `get_model_config/get_vl_model_config` 保留兼容（本地 or 远程）。
- **`llm/client.py`**：
  - `_call(cfg, messages, temperature, timeout)`：单次调用，剥 `<think>` thinking 段；
  - `_chat_with_fallback(messages, local, remote, ...)`：本地优先，仅对**连接/超时/5xx**降级远程，4xx/鉴权不降级；
  - `chat` / `chat_json`（文本，超时 60s）/ `chat_vision`（VL，超时 120s，content 可含 image_url）。

> 依赖：openai SDK、httpx。切换本地↔远程只换 `base_url`+`model`，业务代码零改动。

---

## 4. 记忆层 `memory/store.py`

- **`RemoteEmbeddingFunction`**：调 spark-71 bge 服务的 `/v1/embeddings`（OpenAI 兼容），实现 chromadb 1.x EF 协议（`__call__` + `embed_documents` + `embed_query` + `name`）。**演示机不再装 torch**。
- **`MemoryStore(path, embedding_url)`**：chromadb `PersistentClient` + `bug_issues` collection；`ingest_issue(issue, timeline, top_files)` / `query_similar(timeline, actions, top_k)` / `list_all()`。
- **`get_memory_store()`**：`REPROFORGE_MEMORY=off` 或初始化失败 → None（降级）。

> 依赖：chromadb、requests。embedding 算力在 spark-71，向量库本地持久化。

---

## 5. 采集层 `capture/` + `asr/`

### `capture/recorder.py`
- `RecordingArtifact` / `record(url, actions, out_dir)`：Playwright 录制（screenshots=True，留 trace.zip）。
- `record_user_session(url, timeout)`：用户会话录制。

### `capture/video_parser.py`
- `video_to_segments(video_path)`：imageio-ffmpeg 提音频 → whisper ASR → segments；
- `segments_to_actions(segments)`：LLM 从 segments 提操作序列；
- `video_to_screenshot(video_path, at_ratio)`：opencv 按比例抽帧；
- `parse_video(video_path)`：组合入口（segments + actions + screenshot）。

### `asr/transcribe.py`
- `Segment` / `get_model()` / `transcribe(audio_path)`：faster-whisper（CPU int8，不占 GPU）。

---

## 6. 执行层 `test_runner/` + `minimization/`

### `test_runner/runner.py`
- `RunResult` / `RunTimesResult` / `run_test(spec_path, timeout, cwd)`：跑一次 `npx playwright test --reporter=json`，`_parse_report` 解析 JSON 判通过/失败；
- `run_n_times(spec_path, n, cwd)`：连跑 n 次，汇总稳定率（如 3/3）。

### `minimization/minimize.py`（核心创新，纯确定性）
- `is_candidate_for_removal(action_type, text)`：只删 click/hover 类无关步骤（含"个人中心/帮助/返回"等），保留关键填写（"优惠/券/数量/提交"等）；
- `MinimizeResult` / `minimize(steps, runner, max_attempts=10)`：逐个尝试删除候选步骤 → 子集重生成 spec → runner 真跑 → Bug 仍在(passed=False)则永久删，否则保留；重复直到无可删。**求最短稳定复现路径，不依赖 LLM**。

---

## 7. 检索层 `code_search/search.py`

- `FileHit` / `search(query_terms, repo_path, top_n)`：ripgrep 检索（不可用降级 `_py_matches` 纯 Python 遍历），`_enclosing_context` 用 tree-sitter 提命中所在函数/组件作上下文，按命中数排序取 TopN。

---

## 8. 界面层 `ui/app.py`

Gradio 步骤式 UI（:7860）：`build_app()` 构造「①输入 → ②运行 → ③结果」+ 记忆库列表。
- `record_actions_fn` / `parse_video_fn` / `audio_to_narration_fn`：各输入入口；
- `run_pipeline_ui(...)`：透传给 `run_pipeline(screenshot=...)`，展示复现结果 / VL 视觉 / 测试代码 / Issue；
- `list_memory_fn`：记忆库展示（优雅降级）。

---

## 9. 评测层 `eval/`

- `metrics.py`：`Metrics` / `metrics_from_state(state, latency)` / `run_eval(test_cases, run_pipeline_fn, ...)`——跑用例集算指标；
- `compare.py`：`compare(test_cases, repo_path, project_dir)`——远程 vs 本地 PROFILE 对比（注意切 PROFILE 要重置 `llm.client._client`）。

---

## 10. 部署 `deploy/spark71/` + `scripts/`

- `deploy/spark71/`：`bge_server.py`（FastAPI embedding）+ `download_models.sh`（modelscope）+ `serve_text_vllm.sh`（util 0.45）/ `serve_vl_vllm.sh`（util 0.3）/ `serve_bge.sh`（CPU）+ `start_all.sh`（编排 + 健康检查）+ `modelscope_download.py` / `download_py.py`（下载脚本）。
- `scripts/tunnel.sh`：本地三端口 SSH 隧道（8000/8001/8002 → spark-71）。

---

## 11. 模块依赖关系

```
ui/app ──► graph/workflow ──► agents/* ──► llm/client ──► config
              │                   │           │
              │                   ├─► memory/store ──► (远程 bge)
              │                   ├─► test_runner ──► Playwright
              │                   ├─► code_search ──► ripgrep/tree-sitter
              │                   └─► minimization
              └─► capture/* ──► asr (whisper) / opencv / ffmpeg
deploy/spark71 ──► spark-71 三服务（文本/VL vLLM + bge）
scripts/tunnel ──► 本地 ↔ spark-71 端口转发
```

**分层原则**：`graph` 编排不含业务逻辑，业务在 `agents`；`agents` 不直接碰 OpenAI/Chroma，经 `llm`/`memory` 抽象；确定性底座（Playwright / minimize / code_search）与 LLM 理解层分离，LLM 只负责理解与生成，Bug 是否复现由真实回放判定。
