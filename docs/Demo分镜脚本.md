# ReproForge Demo 视频分镜脚本

> 时长 3-5 分钟 · 中文解说 · 预赛提交用
> 录制：liwenY（tz 审稿）· 操作画面用屏幕录制（OBS / 系统录屏，1080p）

## 整体节奏
项目痛点 → 演示操作 → 4-agent 流水线 → Bug 复现 → 最小复现 → Issue 生成 → 亮点收尾

---

## 镜头 1 · 开场（0:00-0:25）
**画面**：标题卡「ReproForge — Bug 复现与回归智能体」+ 副标题金句「大模型负责理解 Bug，Playwright 负责证明 Bug」
**解说**：「测试报 Bug，最头疼的是"我这能复现、你那不能"。ReproForge 让 AI 边操作边听你口述，自动复现 Bug、求最小复现、生成回归测试、定位可疑代码，最后吐出一份能直接交的 Issue。」

## 镜头 2 · 被测应用 + Bug 介绍（0:25-0:55）
**画面**：localhost:5173 商城，鼠标操作：加商品 → 填优惠码 SALE20 → 点应用（总价变 80）→ 改数量 2（总价仍 80，应 160）。圈出"总价 80"红框。
**解说**：「这是一个预埋了 Bug 的商城 Demo。我用了八折券，把数量改成 2，优惠后总价应该是 160——但页面还显示 80。Bug 复现了。」

## 镜头 3 · 测试员操作 + 口述（0:55-1:35）
**画面**：分屏——左：Gradio UI 输入框（操作步骤 JSON + 口述文本）；右：应用操作回放
**解说**：「测试员边操作边口述：'我用了八折券，数量改成 2，总价还是 80，应该是 160'。ReproForge 采集操作步骤和语音转写。」

## 镜头 4 · 4-agent 流水线（1:35-2:50）
**画面**：4 个 agent 方框连线（evidence → reproduction → code_investigator → regression），逐个高亮 + 输出弹窗。可用静态图/PPT 动画。
**解说**：
- 「第一个 agent，证据分析：从口述里提取出预期 160、实际 80。」
- 「第二个，复现工程：自动生成一个 Playwright 测试，断言总价应为 160。」
- 「第三个，代码调查：检索代码，定位到总价计算逻辑所在文件。」
- 「第四个，回归审查：生成一份 Markdown Bug Issue。」

## 镜头 5 · Bug 复现（红色失败）（2:50-3:30）
**画面**：Playwright 跑测试的真实输出（取自 `spike/smoke_phase3.py` 跑 Bug1 的截图）：`expect(toHaveText) Expected "160", Received "80"`，红色失败。
**解说**：「生成的测试真跑了一遍——断言总价应为 160，实际收到 80，红色失败。这就是 Bug 被客观复现的证据，不是猜的，是跑出来的。」

## 镜头 6 · 最小复现（3:30-4:10）
**画面**：步骤对比（原始操作步骤 N 步 → 最小复现更少步），稳定率 3/3。
**解说**：「系统还会尝试删掉无关步骤，求出最短稳定复现路径——稳定率 3 次全复现。开发拿到这个，复现 Bug 照着点就行。」

## 镜头 7 · Issue 生成（4:10-4:50）
**画面**：生成的 Markdown Issue（预期 / 实际 / 最小复现步骤 / 稳定率 / 可疑代码 App.tsx）。
**解说**：「最后自动生成一份 Issue：预期、实际、最小复现步骤、稳定率、可疑代码位置——测试员直接提交，不用手写。」

## 镜头 8 · 亮点收尾（4:50-5:00）
**画面**：技术栈 logo（LangGraph / Playwright / Stepfun / DGX Spark）+ 团队名 taostronger。
**解说**：「LangGraph 编排多智能体，Playwright 提供确定性底座，双轨模型——开发用远程 API，Demo 本地部署。ReproForge，让 Bug 复现不再是玄学。」
