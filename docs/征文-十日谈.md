# ReproForge 十日谈：让 Bug 复现不再是玄学

> 队伍 taostronger · NVIDIA DGX Spark 多模态 Agent 黑客松 · 2026

## Day 0：一个让人抓狂的老问题

测试报 Bug，开发最怕听到一句话——"我这能复现，你那怎么不能？"

复现 Bug 这件事，高度依赖运气和记忆力。测试员记得自己点了哪、输了什么，可换成开发的环境就死活复现不出来。录像？录了。截图？截了。但操作步骤藏在脑子里，落到代码里就走了样。

我们想用 Agent 解决它：**让大模型负责理解 Bug，让 Playwright 负责证明 Bug**。测试员边操作网页边口述，AI 自动把口述变成可运行的回归测试，真跑一遍证明 Bug 存在，再求出最短复现路径，最后生成一份能直接提交的 Issue。

这就是 ReproForge。

## Day 1：五道闸门决定立项

单人参赛，容不得方向选错。第一天我们设了五道"立项闸门"，用最小代价验证核心技术链路能不能跑通：

1. **操作能不能被采集？** Playwright 录屏拿到了 43KB 的 trace，含 goto / fill / click 四个事件和截图。
2. **语音能不能被理解？** faster-whisper 把"我把数量改成 2，总价还是 80"准确转写成文字。
3. **AI 能不能据此生成测试？** Stepfun `step-3.7-flash` 生成了带 `toHaveText('160')` 断言、用 `data-testid` 定位器的高质量 Playwright 测试。
4. **Bug 能不能被复现？** 真跑一遍——优惠码 apply 后总价 80，改数量 2 后仍 80（应 160），红色失败。
5. **证据能不能落盘？** trace.zip 和生成的测试代码都已输出。

5/5 全过，ReproForge 正式立项。其中第三道闸门（AI 理解 Bug → 生成可运行测试）质量超出预期，成了我们最大的底气。

## 那些只有真跑才会踩的坑

开发全程我们守着一条铁律：**每个模块写完，立刻真调一遍端到端冒烟，不靠 mock 自欺**。

结果就是——mock 测试全绿，真调却炸出四个真实 Bug：

- 生成的测试代码被包在 ` ``` ` 代码围栏里，Playwright 直接报语法错；
- 生成的测试漏了 `import`；
- Windows 下路径正则失配；
- 测试产物污染了下一轮运行。

这四个 Bug 没有一个被 mock 抓到。这件事让我们彻底坚定了"冒烟驱动"：AI 写的代码必须真跑，跑红了的才算数。

环境也没少折腾。DGX Spark 服务器上 GitHub 走 HTTPS 被墙、只有 SSH 22 端口通；下载 Whisper 模型要同时设国内 HF 镜像（`HF_ENDPOINT=hf-mirror.com`）和禁用新版 Xet 协议（`HF_HUB_DISABLE_XET=1`），否则 401；非交互 shell 不加载 nvm，每次远程跑 node 都得手动 source。每一个坑都写进文档，成了后续开发的护栏。

## 最小复现：一个被逼出来的核心创新

最初我们只想"复现 Bug"。跑通后发现新问题：生成的测试里有大量无关步骤——浏览、来回点击、滚动——开发拿到手还是要点十几下。

于是"最小复现"算法诞生：拿到能稳定复现的测试后，逐个尝试删除"候选可删步骤"，删完重跑，Bug 还在就永久删除，否则放回去。最终求出**最短稳定复现路径**，稳定率仍保持 3/3。

这成了 ReproForge 的核心创新，也是我们最得意的部分——它不是一开始设计出来的，是被真实痛点逼出来的。

## 双轨模型：开发用远程，演示用本地

赛题明确要求体现 DGX Spark 的本地算力，但我们不想被本地显存拖慢迭代。解法是双轨：

- **开发期**调 Stepfun 远程 API，迭代快、不占本地显存；
- **演示期**切本地模型（DGX Spark 上的 vLLM 托管 qwen3.6），满足"本地算力部署"的评审要求。

关键在模型调用层做了 OpenAI 兼容抽象：Stepfun 和本地 vLLM 都是 OpenAI 接口，切换只换 `base_url` 和 `model`，业务代码一行不改，一个 `PROFILE=local` 环境变量搞定。

## 一个开发者和一个"审美总监"

taostronger 的实际产能是一个开发者。所以 MVP 的每个功能都备了降级方案：evidence 低置信度就转人工确认，reproduction 不稳定就限定两轮定位器修复，检索没有 ripgrep 就退化成纯 Python 遍历，LLM 不可用就用确定性 fallback 生成 Issue。**不交 = 0 分**，所以我们确保任何一环出问题，系统都不会整个崩。

另一半功劳属于队友 liwenY——她不写代码，但负责被测商城的 Bug 场景设计、Demo 视频的录制剪辑、界面审美把控。技术活我一个人能扛，但"让人看得下去"这件事，需要她。

## 写在最后：Agent 该交付结果，而不是给建议

ReproForge 想说的其实就一件事：**Agent 不该只给建议，该直接交付结果**。

我们没让它说"这个 Bug 可能和优惠码逻辑有关"——我们让它真跑出一个红色失败的测试、求出最短复现路径、生成一份能直接提交的 Issue。测试员不用手写，开发照着点就能复现。

这正合 NVIDIA 对 Agentic AI 的定义：从"给建议的工具"到"自主交付结果的智能体"。LangGraph 编排四个 Agent，Playwright 提供确定性底座，DGX Spark 提供本地算力——三者凑齐，Bug 复现就不再是玄学。
